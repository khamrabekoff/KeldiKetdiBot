# 🤖 Keldi-Ketdi Bot

Telegram-бот учёта прихода/ухода сотрудников и расчёта зарплаты.
Интерфейс — узбекский. Документация — русская.

> ⚠️ Это **не** тушлик-бот (@ovqat_climadens_bot). Это отдельный проект
> на отдельном сервере. Не путать.

---

## Что делает

**Сотрудник** отмечает приход и уход двумя кнопками. Бот считает
отработанное время и зарплату, показывает живую карточку статуса.
Взятые до зарплаты деньги сотрудник записывает сам — кнопкой **💸 Avans**.

**Администратор** видит дашборд «кто сейчас работает» с текущими суммами,
управляет сотрудниками и ставками, выгружает отчёты, правит время задним
числом и рассматривает заявки на исправление.

## Структура кода

```
app.py           Flask-маршруты, runtime, все обработчики Telegram
ui.py            Весь внешний вид: карточки и клавиатуры
database.py      Работа с SQLite, резервное копирование
settings.py      Настройки, изменяемые из бота (часы работы)
analytics.py     Расчёты статистики (без оформления)
utils.py         Время (Ташкент) и расчёт зарплаты
audit.py         Журнал действий администратора
excel_export.py  Отчёты Excel с диаграммами
pdf_export.py    Отчёты PDF
messages.py      Старые текстовые константы (постепенно уходят в ui.py)
```

**Правило:** весь пользовательский текст и вёрстка — в `ui.py`.
Остальные модули возвращают данные, а не готовые сообщения.

### Как сотрудник появляется в системе

Админ вводит имя, телефон и ставку — строка ложится в `pending_users`.
Telegram ID у неё ещё нет, поэтому в `users` она попасть не может: ID
известен только когда человек сам напишет боту и отправит свой номер
(`promote_pending_to_user`).

Пока этого не произошло, сотрудник виден в разделе **⏳ Kutilmoqda** на
экране «Xodimlar» — с телефоном и кнопкой снять приглашение. Ключ строки —
телефон, так что опечатку в нём повторным добавлением не исправить: старое
приглашение надо снять.

## Типы зарплаты

- `monthly` — месячный оклад ← **используется**
- `per_minute` — ставка × отработанные минуты ← **используется**
- `tariff` — 4 временных диапазона с разными ставками (про запас)

### Месячный оклад

Оклад делится на **рабочие дни месяца**, а рабочий день — на минуты
стандартного дня (по умолчанию 09:00–18:00, то есть 540 минут). Получается
ставка за минуту:

```
ставка = оклад / (рабочие дни × минуты стандартного дня)
```

Рабочие дни = календарные дни − воскресенья − официальные выходные.
Например, в месяце 30 дней, 4 воскресенья и 2 официальных выходных → 24
рабочих дня.

За каждый день начисляется:

| Ситуация | Что считается |
|---|---|
| Отработан стандартный день | Полная база: `оклад / рабочие дни` |
| Пришёл позже или ушёл раньше | Недостающие минуты вычитаются по ставке |
| Пришёл раньше или ушёл позже | Лишние минуты добавляются по ставке переработки |
| Не пришёл вовсе | За этот день ноль |
| Вышел в воскресенье или праздник | Все минуты идут как переработка |

Отработал стандартный день во все рабочие дни — за месяц выходит **ровно
оклад**.

Ставка переработки по умолчанию равна базовой. Админ может задать свою: при
вводе оклада бот показывает автоматическую и предлагает прислать `0`, чтобы
её оставить. Своя ставка хранится в `rates.overtime_per_minute`.

Границы стандартного дня берутся из настроек **⚙️ Sozlamalar**, а не зашиты
в код: сдвинув «Ish tugashi», админ сдвигает и расчёт.

> Зарплата за день записывается в `attendance.total_wage` в момент ухода.
> Число рабочих дней меняется, когда админ добавляет выходной задним числом,
> поэтому такие правки запускают пересчёт всего месяца
> (`database.recalculate_month_wages`).

### Как показываются суммы

Валюта — доллары: `$208,333.33`. Решает это один блок констант в начале
`utils.py` — префикс, суффикс, число знаков после запятой, разделитель
разрядов и формат для Excel. Всё остальное читает их: `ui.fmt_money` для
экранов бота, `utils.format_rate` для ставок (у ставки своя точность —
`$0.036` не должно округляться до `$0.04`), `excel_export` и `pdf_export`
для выгрузок. Сменить валюту — это правка того блока, а не проход по шести
файлам; в комментарии там же записано, что поставить для сумов.

Внутри `<code>`-колонок валюта убирается (`fmt_money(x, unit=False)`), иначе
строка переносится на телефоне, — единица уходит в заголовок столбца.

### Что видно в отчётах

Вместе с итогом за день хранится его разбивка: `attendance.base_wage` и
`attendance.overtime_wage`. Считать её на лету нельзя — если админ поменяет
оклад, пересчитается только текущий месяц, и разбивка по прошлым месяцам
разошлась бы с сохранёнными суммами.

Разбивка видна и сотруднику, и админу:

| Где | Что показывает |
|---|---|
| 📊 Hisobim (сотрудник) | Отработано дней из рабочих, оклад, переработка, итог |
| Карточка сотрудника (админ) | То же плюс ставка и текущий статус |
| 📊 Hisobot за месяц | По каждому: оклад + переработка = итог, и общий итог по бонусам. Считаются только дни выбранного месяца — до сентября 2026 отчёт за прошлый месяц захватывал и все следующие |
| PDF | Строки «Asosiy to'lov» и «Qo'shimcha» |
| Excel | Разбивка по каждому дню в колонке «Tafsilot» |

Строки с переработкой появляются, только если она есть. У минутной ставки
разбивки нет — там вся сумма это отработанные минуты, делить не на что, и
карточка остаётся с одной суммой.

Записи, сделанные до появления этих колонок, хранят нули: такие дни целиком
считаются окладом, что для минутной ставки и было правдой.

## Авансы

Сотрудник сам записывает деньги, взятые до зарплаты: **💸 Avans** → сумма →
описание → подтверждение. Описание необязательно — его пропускает кнопка
«⏭ Izohsiz».

Запись сразу уходит всем админам: имя, сумма, описание и сколько авансов
сотрудник взял за месяц.

Если деньги выдаёт сам админ, он записывает аванс за сотрудника:
**👥 Xodimlar → сотрудник → 💸 Avans berish**, дальше те же шаги. Сотруднику
приходит сообщение, остальным админам — та же карточка с пометкой, кто из
админов записал (`advances.created_by`). Под сообщением кнопка **❌ Bekor qilish** — для
ошибочных записей. Отменённый аванс не удаляется: строка остаётся в таблице
`advances` со статусом `VOID` и тем, кто отменил. Сотруднику приходит
сообщение об отмене.

Аванс относится к месяцу, в котором записан, и вычитается из заработка
этого месяца. Разница — сколько админу осталось заплатить: у сотрудника
она называется **Qoldiq**, в отчётах админа — **To'lash kerak**.

| Где | Что показывает |
|---|---|
| 📊 Hisobim (сотрудник) | Сумма авансов, остаток, список с описаниями |
| Карточка сотрудника (админ) | То же |
| 📊 Hisobot за месяц | По каждому: заработок − аванс = к выплате; итог «TO'LASH KERAK» |
| Excel | Первый лист «To'lov»: Ism · Kunlar · Ish haqi · Avans · To'lash kerak; лист «Avanslar» со всеми авансами и описаниями |
| PDF | После таблицы дней — таблицы «To'lov» и «Avanslar» |

Все три отчёта берут цифры из одной функции, `analytics.month_payroll`, так
что расходиться не могут.

К выплате бывает отрицательным: в середине месяца аванс может быть больше
уже заработанного.

Если заработок сотруднику скрыт, свои авансы он видит, а остаток нет — по
остатку легко восстановить заработок.

PDF печатается шрифтом DejaVu, если он есть на сервере (на PythonAnywhere
есть): встроенный Helvetica не умеет кириллицу, и описания или имена на
кириллице выходили чёрными квадратами.

## Выплата зарплаты

**📊 Hisobot → месяц → 💰 To'lov** — список сотрудников с суммой к выплате.
Выбрав сотрудника, админ видит, из чего сумма сложилась, и одну из кнопок:

| Кнопка | Когда | Что делает |
|---|---|---|
| ✅ $X to'landi | к выплате больше нуля | Записывает выплату ровно этой суммы |
| 🔒 Oyni yopish | к выплате ноль или меньше | Закрывает месяц без выплаты |
| ✏️ Boshqa summa | всегда | Выплата другой суммы — частично или больше долга |
| 🗑 … bekor qilish | у каждой выплаты | Отменяет ошибочную запись (`VOID`, не удаление) |

Сотруднику приходит сообщение о выплате. Если заработок ему скрыт — без суммы.

Выплаты хранятся в таблице `payments`: сотрудник, **месяц, за который
платят**, сумма, кто записал. Месяц с хотя бы одной выплатой считается
**закрытым**, и всё, что в нём осталось, переходит в следующий месяц строкой
**O'tgan oydan**:

```
к выплате = O'tgan oydan + заработок − авансы − выплачено
```

Аванс больше зарплаты → после закрытия месяца минус уходит в следующий и
вычитается оттуда. Недоплатил часть → остаток прибавится в следующем.

Переносится **только из закрытого** месяца. Месяцы, оплаченные мимо бота —
то есть все до появления выплат, — не переносят ничего, иначе каждый из них
всплыл бы долгом.

Кнопка «✅ to'landi» несёт в себе показанную сумму. Если к моменту нажатия
сумма изменилась — второй админ уже заплатил, поправили день, — выплата не
записывается, экран перерисовывается с новыми цифрами. Так два админа не
заплатят дважды.

Колонки «O'tgan oydan» и «To'langan» появляются в Excel и PDF, только если в
этом месяце есть перенос или выплаты.

## Настройки из бота

Кнопка **⚙️ Sozlamalar** в панели администратора:

- 🕘 Начало рабочего дня
- ⏰ Порог опоздания
- 🕕 Конец рабочего дня
- 💰 Видит ли сотрудник свой заработок
- 📅 Официальные выходные

Хранятся в таблице `settings` и **общие для всех админов** этого клиента.

### Видит ли сотрудник свой заработок

По умолчанию **да** — так работали все существующие установки. Выключенный
переключатель убирает деньги со всех экранов сотрудника разом: живая карточка
статуса, «📊 Hisobim», месячный отчёт и сообщение после ухода. Время, статус и
заявки на исправление остаются — сотрудник ведёт учёт часов, но не видит сумм.

У администратора не меняется ничего.

База у каждого клиента своя, поэтому переключатель — политика одного клиента,
а не общая настройка кода.

### Официальные выходные

Отдельный экран с помесячной навигацией. Показывает, сколько в месяце рабочих
дней и из чего это число сложилось. Дни вводятся числами через запятую —
`8, 9`, при желании с пояснением: `8, 9 | Mustaqillik kuni`.

Воскресенья вводить не нужно, они исключаются сами. Хранятся в таблице
`holidays`, действуют на всех сотрудников. Добавление и удаление дня сразу
пересчитывает зарплаты этого месяца.

## Автоматика

| Когда | Что |
|---|---|
| 08:30 | Напоминание тем, кто не отметил приход |
| После конца рабочего дня | Напоминание тем, кто не отметил уход |
| Понедельник утром | Недельная сводка админам + резервная копия базы |

В воскресенье и в официальный выходной напоминания сотрудникам не уходят —
на работу их никто не ждёт. Понедельничная сводка и резервная копия
отправляются всё равно: они для админа, и праздничный понедельник не должен
стоить недельного бэкапа.

Напоминания отправляются либо задачей по расписанию (там, где она есть),
либо на обычном трафике бота — что сработает первым. Подробности и
ограничения — в [DEPLOY.md](DEPLOY.md).

## Резервные копии

База уходит админам файлом в Telegram: автоматически по понедельникам
и по команде `/backup`.

Снимок делается через встроенный механизм SQLite, а не копированием файла —
база работает в режиме WAL, и обычная копия может потерять последние записи.

**Восстановление** описано в [DEPLOY.md](DEPLOY.md).

## Тесты

```bash
pip install -r requirements.txt
python tests/test_monthly.py    # формула месячного оклада
python tests/test_reports.py    # разбивка оклад/переработка в отчётах
python tests/smoke_test.py      # сборка бота, экран праздников, разбор ввода
python tests/test_advances.py   # авансы: запись, уведомление, отчёты, Excel/PDF, отмена
python tests/test_payments.py   # выплаты, перенос между месяцами, аванс от админа
```

Каждый файл запускается сам по себе, работает на временной базе в системной
папке и ничего не трогает в рабочих данных. Код возврата ненулевой при
падении, так что их можно повесить в CI.

На Windows вместо `python` обычно нужен `py`. Вывод с эмодзи тесты печатают
сами в UTF-8, так что cp1251 в консоли им уже не мешает.

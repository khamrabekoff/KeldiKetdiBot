# 🤖 Keldi-Ketdi Bot

Telegram-бот учёта прихода/ухода сотрудников и расчёта зарплаты.
Интерфейс — узбекский. Документация — русская.

> ⚠️ Это **не** тушлик-бот (@ovqat_climadens_bot). Это отдельный проект
> на отдельном сервере. Не путать.

---

## Что делает

**Сотрудник** отмечает приход и уход двумя кнопками. Бот считает
отработанное время и зарплату, показывает живую карточку статуса.

**Администратор** видит дашборд «кто сейчас работает» с текущими суммами,
управляет сотрудниками и ставками, выгружает отчёты, правит время задним
числом и рассматривает заявки на исправление.

## Типы зарплаты

- `monthly` — месячный оклад ← **используется**
- `per_minute` — ставка × отработанные минуты ← **используется**
- `tariff` — 4 временных диапазона с разными ставками (про запас)

### Месячный оклад

Оклад делится на **рабочие дни месяца**, а рабочий день — на минуты
стандартного дня (по умолчанию 09:00–18:00, то есть 540 минут). Получается
ставка за минуту:

```
ставка = оклад / (рабочие дни × минуты стандартного дня)
```

Рабочие дни = календарные дни − воскресенья − официальные выходные.
Например, в месяце 30 дней, 4 воскресенья и 2 официальных выходных → 24
рабочих дня.

За каждый день начисляется:

| Ситуация | Что считается |
|---|---|
| Отработан стандартный день | Полная база: `оклад / рабочие дни` |
| Пришёл позже или ушёл раньше | Недостающие минуты вычитаются по ставке |
| Пришёл раньше или ушёл позже | Лишние минуты добавляются по ставке переработки |
| Не пришёл вовсе | За этот день ноль |
| Вышел в воскресенье или праздник | Все минуты идут как переработка |

Отработал стандартный день во все рабочие дни — за месяц выходит **ровно
оклад**.

Ставка переработки по умолчанию равна базовой. Админ может задать свою: при
вводе оклада бот показывает автоматическую и предлагает прислать `0`, чтобы
её оставить. Своя ставка хранится в `rates.overtime_per_minute`.

Границы стандартного дня берутся из настроек **⚙️ Sozlamalar**, а не зашиты
в код: сдвинув «Ish tugashi», админ сдвигает и расчёт.

> Зарплата за день записывается в `attendance.total_wage` в момент ухода.
> Число рабочих дней меняется, когда админ добавляет выходной задним числом,
> поэтому такие правки запускают пересчёт всего месяца
> (`database.recalculate_month_wages`).

### Как показываются суммы

Валюта — сумы. `ui.fmt_money` печатает `5 231 481 so'm`: разряды через
пробел, копеек нет — при окладах в миллионах они ничего не значат. Внутри
`<code>`-колонок суффикс убирается (`fmt_money(x, unit=False)`), иначе
строка переносится на телефоне, а единица уходит в заголовок столбца. Так же
устроены выгрузки: в Excel числовой формат `#,##0" so'm"`, в PDF — `_money`.

### Что видно в отчётах

Вместе с итогом за день хранится его разбивка: `attendance.base_wage` и
`attendance.overtime_wage`. Считать её на лету нельзя — если админ поменяет
оклад, пересчитается только текущий месяц, и разбивка по прошлым месяцам
разошлась бы с сохранёнными суммами.

Разбивка видна и сотруднику, и админу:

| Где | Что показывает |
|---|---|
| 📊 Hisobim (сотрудник) | Отработано дней из рабочих, оклад, переработка, итог |
| Карточка сотрудника (админ) | То же плюс ставка и текущий статус |
| 📊 Hisobot за месяц | По каждому: оклад + переработка = итог, и общий итог по бонусам |
| PDF | Строки «Asosiy to'lov» и «Qo'shimcha» |
| Excel | Разбивка по каждому дню в колонке «Tafsilot» |

Строки с переработкой появляются, только если она есть. У минутной ставки
разбивки нет — там вся сумма это отработанные минуты, делить не на что, и
карточка остаётся с одной суммой.

Записи, сделанные до появления этих колонок, хранят нули: такие дни целиком
считаются окладом, что для минутной ставки и было правдой.

## Настройки из бота

Кнопка **⚙️ Sozlamalar** в панели администратора:

- 🕘 Начало рабочего дня
- ⏰ Порог опоздания
- 🕕 Конец рабочего дня
- 📅 Официальные выходные

Первые три хранятся в таблице `settings` и **общие для всех админов**.

### Официальные выходные

Отдельный экран с помесячной навигацией. Показывает, сколько в месяце рабочих
дней и из чего это число сложилось. Дни вводятся числами через запятую —
`8, 9`, при желании с пояснением: `8, 9 | Mustaqillik kuni`.

Воскресенья вводить не нужно, они исключаются сами. Хранятся в таблице
`holidays`, действуют на всех сотрудников. Добавление и удаление дня сразу
пересчитывает зарплаты этого месяца.

## Автоматика

| Когда | Что |
|---|---|
| 08:30 | Напоминание тем, кто не отметил приход |
| После конца рабочего дня | Напоминание тем, кто не отметил уход |
| Понедельник утром | Недельная сводка админам + резервная копия базы |

В воскресенье и в официальный выходной напоминания сотрудникам не уходят —
на работу их никто не ждёт. Понедельничная сводка и резервная копия
отправляются всё равно: они для админа, и праздничный понедельник не должен
стоить недельного бэкапа.

Напоминания отправляются либо задачей по расписанию (там, где она есть),
либо на обычном трафике бота — что сработает первым. Подробности и
ограничения — в [DEPLOY.md](DEPLOY.md).

## Резервные копии

База уходит админам файлом в Telegram: автоматически по понедельникам
и по команде `/backup`.

Снимок делается через встроенный механизм SQLite, а не копированием файла —
база работает в режиме WAL, и обычная копия может потерять последние записи.

**Восстановление** описано в [DEPLOY.md](DEPLOY.md).

## Тесты

```bash
pip install -r requirements.txt
python tests/test_monthly.py    # формула месячного оклада
python tests/test_reports.py    # разбивка оклад/переработка в отчётах
python tests/smoke_test.py      # сборка бота, экран праздников, разбор ввода
```

Каждый файл запускается сам по себе, работает на временной базе в системной
папке и ничего не трогает в рабочих данных. Код возврата ненулевой при
падении, так что их можно повесить в CI.

На Windows вместо `python` обычно нужен `py`. Вывод с эмодзи тесты печатают
сами в UTF-8, так что cp1251 в консоли им уже не мешает.
